# Kotlin Multiplatform on NixOS — Android + Linux Desktop

Kotlin Multiplatform (KMP) with **zero Android Studio, zero emulators**. You code in **nixvim**, test on **Linux desktop** (fast loop), and deploy to a **physical Android device** over USB/wireless adb.

---

## 0. One-time setup

```fish
rebuild-system
```

That single rebuild delivers everything:

**System layer (`system/jinnnn/android-dev.nix`)**
| What | Why |
|---|---|
| `android-dev-env` (buildFHSEnv) | FHS shell where Gradle/AGP can download and run its own `aapt2`, `d8`, CMake, NDK toolchains. Required on NixOS — prebuilt binaries expect `/lib64/ld-linux-x86-64.so.2` |
| Android SDK via `androidenv.composeAndroidPackages` | platform-35, build-tools 35.0.0, cmdline-tools, platform-tools. **No emulator, no system images, no Android Studio** |
| `services.udev.packages = [ android-udev-rules ]` | Physical device shows up in `adb devices` (Pixel/Samsung/Xiaomi/OnePlus/… all covered) |
| `nixpkgs.config.android_sdk.accept_license = true` | Accepts the SDK license declaratively |
| `android-tools` on host | `adb`/`fastboot` available outside the FHS shell |

**Home layer (`home/meher/packages.nix`)**
`kotlin`, `gradle`, `ktlint`, `jdk17`, `kotlin-language-server` — the desktop/Linux toolchain, available in your normal shell.

**Nixvim layer**
- `kotlin_language_server` (fwcd) with root markers for Gradle projects → completion, diagnostics, hover, code actions, rename.
- treesitter parsers: `kotlin`, `java`, `groovy`, `toml`, `xml`, `yaml`, `json` — covering `.kt`, `.kts`, `build.gradle`, `libs.versions.toml`, `AndroidManifest.xml`, `res/*.xml`.
- Keymaps: `<leader>ca` (code actions via actions-preview), `<leader>rn` (rename), plus your existing `K` hover, `<C-Space>` signature, `<leader>td` diagnostics.

## 1. First project

Generate a KMP project with the JetBrains wizard: https://kmp.jetbrains.com — choose **Android** + **Desktop** targets, then:

```fish
cd ~/dev/my-app
```

## 2. The daily workflow (nixvim + terminal only)

### Linux desktop testing (primary loop)

```fish
# Without the FHS shell — pure JVM/desktop, fast iteration
./gradlew :composeApp:run
```

This launches the Compose Multiplatform desktop window. No Android bits needed for this loop, so it works in your normal fish shell.

### Android device testing

Gradle must run **inside the FHS shell** (AGP downloads its own aapt2 which only runs there):

```fish
android-dev-env
./gradlew :composeApp:installDebug
adb devices   # sanity-check the device is visible
```

- Enable **Developer options → USB debugging** on the phone, accept the fingerprint prompt when prompted.
- Launch the app on the phone afterward, or `adb shell am start -n your.package.name/.MainActivity`.
- Logs: `adb logcat --pid=$(pidof your.package.name)` or just `adb logcat | grep yourtag`.
- **Wireless adb** (after first USB pairing): `adb tcpip 5555 && adb connect <phone-ip>:5555`.

### Signing / release APK

```fish
./gradlew :composeApp:assembleRelease
```

## 3. Editor workflow in nixvim

| Action | Keymap |
|---|---|
| Code actions / quick-fix / optimize imports | `<leader>ca` |
| Rename symbol (across files) | `<leader>rn` |
| Hover docs | `K` |
| Signature help | `<C-Space>` |
| Diagnostics list | `<leader>td` |
| Go to definition / references | built-in LSP (`gd`, `gr`, `grr`) defaults |

- `kotlin_language_server` starts when you open any `.kt` / `.kts` file inside a Gradle project.
- First completion may take a few seconds while the server indexes Gradle models — it's a one-time hit per project.
- `actions-preview` shows the diff before applying a code action.
- Kotlin stdlib/Compose sources: the server resolves them from the Gradle cache after the first build, so run a build once before expecting deep navigation into framework code.

## 4. Where things live (NixOS notes)

- Android SDK: read-only Nix store path (`$ANDROID_HOME` inside `android-dev-env`).
- Gradle caches: `~/.gradle` (shared across all projects, survives rebuilds).
- **Never** run `sdkmanager --install` to add SDK components — that mutates the read-only store path. Add them declaratively in `android-dev.nix` instead.
- `local.properties` with `sdk.dir` is auto-generated by AGP from `$ANDROID_HOME` inside the shell; don't commit it (it's in `.gitignore` by default in KMP templates).

## 5. Troubleshooting

| Symptom | Fix |
|---|---|
| `adb devices` empty | Check USB mode is "File transfer/MTP" or re-accept the phone's debugging prompt; `sudo udevadm control --reload && sudo udevadm trigger` after rebuild |
| `adb: no permissions` | `android-udev-rules` should prevent this; re-plug after rebuild |
| "SDK location not found" | Run Gradle inside `android-dev-env` (it exports `ANDROID_HOME`) or create `local.properties` with `sdk.dir=<sdk path>` |
| `AAPT2 aapt2-... Daemon startup failed` | You ran Gradle outside the FHS shell — re-enter `android-dev-env` |
| `Unsupported class file major version` | JDK mismatch — the shell exports `JAVA_HOME` to JDK 17; make sure the project's `kotlin { jvmToolchain(17) }` (or project gradle.properties) agrees |
| KLS slow first completion | Gradle model import is one-time per project; subsequent starts are fast |
| `kotlin_language_server` not attaching | Open a file inside the Gradle project root; check `:LspInfo` |

## 6. Why no emulator (and what you'd add if you change your mind)

- **No emulator is needed** for your stated workflow: Linux desktop covers daily testing; the physical device covers Android-specific behavior.
- If you ever want one: set `includeEmulator = true` and `includeSystemImages = true` in `android-dev.nix`, run `avdmanager create avd ...` inside the shell, and add your user to the `kvm` group. That's the only change needed — everything else (licenses, udev, shell) is already in place.
